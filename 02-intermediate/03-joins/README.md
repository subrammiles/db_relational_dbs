# 03 · Joins

A join combines rows from two or more tables based on a related column.

```sql
SELECT ...
FROM left_table  l
[INNER | LEFT | RIGHT | FULL] JOIN right_table r ON r.key = l.key;
```

## Join types at a glance

```
     A       B           INNER JOIN      LEFT JOIN       RIGHT JOIN      FULL JOIN
   ┌───┐   ┌───┐           ┌─┐           ┌───┬─┐           ┌─┬───┐       ┌───┬─┬───┐
   │   │ ∩ │   │           │█│           │███│█│           │█│███│       │███│█│███│
   └───┘   └───┘           └─┘           └───┴─┘           └─┴───┘       └───┴─┴───┘
                       only matches   all of A +        all of B +      everything
                                      matches of B      matches of A
```

| Join | Returns | Unmatched rows |
|---|---|---|
| `INNER JOIN` (or just `JOIN`) | Only rows with a match on both sides | Dropped |
| `LEFT [OUTER] JOIN` | Every row of the left table + matches | Right side columns are NULL |
| `RIGHT [OUTER] JOIN` | Every row of the right table + matches | Left side columns are NULL |
| `FULL [OUTER] JOIN` | Every row of both tables | NULLs on whichever side is missing |
| `CROSS JOIN` | Every combination (Cartesian product): rows(A) × rows(B) | — |
| Self join | A table joined to itself (e.g. employee → manager) | Depends on join type |
| `NATURAL JOIN` | Inner join on **all** columns with the same name | Dropped |
| `JOIN ... USING (col)` | Inner join on the named same-named column(s); `col` appears once | Dropped |

`RIGHT JOIN` is just a `LEFT JOIN` with the tables swapped; most teams only write `LEFT JOIN`.

## Patterns you'll use constantly

**Anti-join: rows with no match.** "Customers who never ordered":

```sql
SELECT c.name
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.customer_id
WHERE o.order_id IS NULL;          -- or: WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE ...)
```

**Semi-join: rows that have at least one match, listed once.** Use `EXISTS` (or `IN`), not `JOIN` + `DISTINCT`.

**Self join:** `employees e LEFT JOIN employees m ON m.emp_id = e.manager_id`.

**Non-equi join:** the `ON` condition can be any expression, e.g. `ON e.salary BETWEEN g.min_salary AND g.max_salary` for salary grades.

**Joining 3+ tables:** chain them: `customers → orders → order_items → products`.

## Pitfalls

- **Filtering the right table of a LEFT JOIN in `WHERE` turns it into an INNER JOIN.**
  `LEFT JOIN orders o ON ... WHERE o.status = 'delivered'` removes customers without orders, because their `o.status` is NULL. Put the condition in the `ON` clause instead: `LEFT JOIN orders o ON o.customer_id = c.customer_id AND o.status = 'delivered'`.
- **Row multiplication (fan-out).** Joining a customer to 4 orders gives 4 rows; summing a customer-level value afterwards counts it 4 times. Aggregate before joining, or use a subquery.
- **NULLs never match** in `ON a.x = b.x`.
- **NATURAL JOIN is fragile:** adding a same-named column (e.g. `created_at`) to both tables silently changes the join. [oracle.sql](oracle.sql) shows this returning 0 rows. Prefer `ON` or `USING`.
- **Forgetting the join condition** (old comma syntax `FROM a, b` without `WHERE`) gives an accidental cross join.

## Interview questions

1. **INNER vs LEFT JOIN?** INNER keeps only matched rows; LEFT keeps every left row and fills NULLs where there's no match.
2. **How do you find rows in A that are not in B?** `LEFT JOIN ... WHERE b.key IS NULL`, `NOT EXISTS`, or `EXCEPT`. Avoid `NOT IN` if B's column can be NULL.
3. **How many rows does a CROSS JOIN of 20 and 30 rows return?** 600.
4. **If A has 5 rows and B has 4, what are the min and max rows of A INNER JOIN B?** Min 0 (no matches), max 20 (every row matches every row, e.g. all keys equal).
5. **And of A LEFT JOIN B?** Min 5, max 20.
6. **What is a self join? Give an example.** A table joined to itself under two aliases: employees and their managers.
7. **Why might a LEFT JOIN return fewer rows than expected?** A `WHERE` condition on the right table removed the NULL-extended rows.
8. **Difference between ON, USING and NATURAL JOIN?** `ON` takes any condition; `USING(col)` joins on equal same-named columns and outputs `col` once; `NATURAL` does `USING` on every common column name automatically.
9. **How do you do a FULL OUTER JOIN in MySQL?** `LEFT JOIN` `UNION` `RIGHT JOIN` (see [mysql.sql](mysql.sql)).
