# 02 · CREATE TABLE and data types

## Syntax

```sql
CREATE TABLE table_name (
    column_name  data_type  [constraints],
    ...
    [table_constraints]
);
```

```sql
CREATE TABLE users (
    user_id     INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name        VARCHAR(100) NOT NULL,
    email       VARCHAR(100) UNIQUE,
    created_at  TIMESTAMP    DEFAULT CURRENT_TIMESTAMP
);
```

## Common data types

| Kind | Standard / PostgreSQL | MySQL | Oracle | Notes |
|---|---|---|---|---|
| Whole number | `SMALLINT`, `INT`, `BIGINT` | same, plus `TINYINT` | `NUMBER(10)` | Pick the smallest that fits forever |
| Exact decimal | `NUMERIC(p,s)` / `DECIMAL(p,s)` | `DECIMAL(p,s)` | `NUMBER(p,s)` | **Use for money.** `NUMERIC(10,2)` = 8 digits before the point, 2 after |
| Approximate | `REAL`, `DOUBLE PRECISION` | `FLOAT`, `DOUBLE` | `BINARY_DOUBLE` | Rounding errors: `0.1 + 0.2 <> 0.3`. Never for money |
| Fixed text | `CHAR(n)` | `CHAR(n)` | `CHAR(n)` | Padded with spaces. Good for codes like `'IN'` |
| Variable text | `VARCHAR(n)`, `TEXT` | `VARCHAR(n)`, `TEXT` | `VARCHAR2(n)`, `CLOB` | |
| Date | `DATE` | `DATE` | `DATE` (**includes time!**) | |
| Date + time | `TIMESTAMP`, `TIMESTAMPTZ` | `DATETIME`, `TIMESTAMP` | `TIMESTAMP` | Store UTC, or use `TIMESTAMPTZ` |
| Boolean | `BOOLEAN` | `BOOLEAN` (= `TINYINT(1)`) | `BOOLEAN` only in 23c; else `NUMBER(1)` | |
| Binary | `BYTEA` | `BLOB` | `BLOB` | |
| JSON | `JSON`, `JSONB` | `JSON` | `JSON` (21c+) | `JSONB` is indexed/binary |
| UUID | `UUID` | `CHAR(36)` / `BINARY(16)` | `RAW(16)` | |

## Auto-incrementing ids

| Database | Syntax |
|---|---|
| Standard / PostgreSQL 10+ / Oracle 12c+ | `id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY` |
| PostgreSQL (old style) | `id SERIAL PRIMARY KEY` |
| MySQL | `id INT AUTO_INCREMENT PRIMARY KEY` |
| SQLite | `id INTEGER PRIMARY KEY [AUTOINCREMENT]` |
| SQL Server | `id INT IDENTITY(1,1) PRIMARY KEY` |
| Oracle (old style) | A `SEQUENCE` plus a trigger, or `DEFAULT seq.NEXTVAL` |

`GENERATED ALWAYS` refuses manual ids; `GENERATED BY DEFAULT` lets you supply one.

## Other ways to create a table

```sql
CREATE TABLE IF NOT EXISTS t (...);                          -- no error if it already exists
CREATE TABLE high_paid AS SELECT * FROM employees WHERE salary > 100000;   -- copy data (CTAS)
CREATE TABLE empty_copy AS SELECT * FROM employees WHERE 1 = 0;           -- copy structure only
CREATE TABLE emp_copy (LIKE employees INCLUDING ALL);        -- PostgreSQL: structure + constraints
CREATE TEMPORARY TABLE scratch (...);                        -- dropped at end of session
```

CTAS copies columns and data but **not** primary keys, foreign keys or indexes.

## Listing and describing tables

| Database | List tables | Describe one |
|---|---|---|
| PostgreSQL | `\dt` | `\d employees` |
| MySQL | `SHOW TABLES;` | `DESCRIBE employees;` |
| Oracle | `SELECT table_name FROM user_tables;` | `DESC employees` |
| SQLite | `.tables` | `.schema employees` |
| Any (standard) | `SELECT table_name FROM information_schema.tables WHERE table_schema = 'public';` | `information_schema.columns` |

## Common mistakes

- Using `FLOAT` for money. Use `NUMERIC`/`DECIMAL`.
- `VARCHAR` without a length in MySQL is an error.
- Oracle `DATE` stores a time too; `WHERE hire_date = DATE '2025-01-15'` misses rows with a time part.
- Forgetting a primary key. Every table should have one.

## Interview questions

1. **CHAR vs VARCHAR?** `CHAR(n)` always stores n characters, padding with spaces; `VARCHAR(n)` stores only what you give it, up to n. Use `CHAR` only for truly fixed-length codes.
2. **Why not FLOAT for currency?** Binary floating point can't represent most decimal fractions exactly, so sums drift. `DECIMAL` is exact.
3. **VARCHAR vs VARCHAR2 in Oracle?** Today they behave the same; Oracle recommends `VARCHAR2` because `VARCHAR` is reserved for possible future semantics.
4. **What does CREATE TABLE AS SELECT copy?** Column names, types and rows. Not constraints, indexes, defaults or triggers.
